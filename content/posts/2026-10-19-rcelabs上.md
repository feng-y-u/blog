# RCELABS（上）：从任意代码执行到只有 7 个字符（Level 0–14）

RCELABS 是一组练习 RCE 的靶场。Level 0–14 的难度来自**一层层加码的过滤**：一开始只要"能让代码跑起来"，到后面只剩 7 个可用字符。

这篇按三条线整理：**概念（执行的是什么）→ shell 基础（命令怎么被解析）→ 绕过手法（过滤怎么被绕开）**。重点不是背 payload，而是搞清楚**每加一层过滤，原来的手法为什么还能用**。

## 一、把概念分清楚

### RCELABS-0：ACE 与 RCE

**任意代码执行（ACE）**是指攻击者在目标计算机或进程中运行攻击者选择的任何命令和代码的能力，涵盖了任何类型的代码运行过程：包括系统层面的命令、程序……以及程序内部的函数或方法调用。

在此基础上，**通过网络触发**任意代码执行的能力，叫做**远程代码执行（RCE）**。

> 记住这个层次关系：ACE 是"能执行"这件事本身，RCE 是"能通过网络触发"。

### RCELABS-2：语句和表达式的区别

代码执行类的漏洞，卡点常常在于"我注入的东西被当成**语句**还是**表达式**"：

- **语句**是"做一件事"，本身没有值（比如 `echo`、`include`）；
- **表达式**会算出一个值，可以嵌在别的东西里面（比如 `1+1`、函数调用）。

能写进参数位置并且被求值的地方，只有表达式；如果只能拼到一个"必须是语句"的位置，payload 的写法就完全不同。同一关里"能不能用括号、能不能用分号"往往就是在卡这条线。

### RCELABS-3：代码执行与命令执行

- **命令执行**通常指的是在**操作系统层面**上执行预定义的指令或脚本，最终指向的通常是系统命令：Windows 的 CMD 命令、Linux 的 Shell 命令。在语言里体现为特定的函数或方法调用，比如 PHP 的 `shell_exec()`、Python 的 `os.system()`。
- **代码执行**则是让目标语言自己"跑一段代码"，比如 PHP 的 `eval()`、`assert()`，或者 `include` 一个可控文件。

两者的绕过思路不一样：命令执行要绕过的是 **shell 的解析规则**；代码执行要绕过的是**目标语言的语法和过滤**。

### RCELABS-1：PHP 的 include 会立刻执行

PHP 中 `include` 引用的**函数会立刻执行**——也就是说，`include` 不是"把文件读进来看看"，而是"把文件当作 PHP 代码**跑一遍**"。所以只要能控制 `include` 的目标（本地文件包含 + 能写文件），就等于拿到了代码执行。

## 二、shell 基础：命令怎么被解析

### RCELABS-4：控制命令执行流程的运算符

| 运算符 | 含义 |
| --- | --- |
| `&&` | 与：`cmd_1` 成功执行，才会执行 `cmd_2` |
| `\|\|` | 或：`cmd_1` 执行失败，才会执行 `cmd_2` |
| `&` | 后台运行：`cmd_1` 放到后台，同时继续执行后面的命令 |
| `;` | 命令分隔：无条件按顺序执行 |

这几个符号决定了"我注入的命令会不会被执行"：

- 目标代码是 `system("ping " . $ip)` 这种拼接时，用 `;` 或 `&&` 就能把后面的命令接上去；
- 如果前面的命令**注定失败**（比如 ping 一个不存在的地址），`&&` 后面的就永远不会执行，这时要用 `||` 或 `;`。

### RCELABS-8：没有回显，可能是被重定向到了 /dev/null

没有回显不一定代表没执行成功——有可能输出被**重定向到 `/dev/null`** 丢掉了。这时可以用分号分隔符，把命令**写进文件**再想办法读，或者直接构造带外回显。

### RCELABS-9（前半）：`system()` 执行的是 sh

在 PHP 中，`system()` 执行命令时实际调用的是 **`sh -c "你的命令"`**，而 `sh` 通常只是一个**软链接**，在不同操作系统上链接到不同的终端程序。

这决定了你能用哪些 shell 语法：

> **注意**：`$'...'`（ANSI-C 转义）、`${##}`、`<<<` 这些都是 **bash 扩展**，严格符合 POSIX 的 `sh`（比如 Debian 系的 `/bin/sh` → `dash`）并不支持。所以同一份 payload，在 sh 指向 bash 的机器上能打通，指向 dash 的机器上可能直接失效。
> （我本机验证用的 Git Bash 是 `5.3.15`，这些扩展都支持。）

### here-string：`<<<`

`<<<` 用来做 **here-string（字符串输入重定向）**：它把右边的字符串当作输入，交给左边启动的 Bash。

这一条在后面 Levels 10、11 很关键：**外层 shell 负责"把二进制转成八进制"，内层 shell 负责"执行八进制"**。写法上要把命令和参数写成两个独立的 `$'...'`，中间**必须加空格**；在外层则要对这个空格进行编码，保证内层能收到一个真正的空格。

## 三、绕过过滤的武器库

### RCELABS-5：通配符绕过

空字符忽略和通配符绕过，可以绕过简单过滤：

| 写法 | 含义 |
| --- | --- |
| `*` | 匹配零个或多个字符 |
| `?` | 匹配单个字符 |
| `[ ]` | 匹配方括号内的任意一个字符，如 `file[1-3].txt` |
| `[^ ]` | 匹配不在方括号内的字符，如 `file[^a-c].txt` |
| `{ }` | 匹配大括号内的任意一个字符串，如 `file{1,2,3}.txt` |

> **注意**：这一组其实是 shell 的**通配符展开（globbing）**，不是"空字符（null byte）"。两者的用途不同：通配符用来**在不知道完整文件名的情况下指到某个文件**（比如 `cat /*g` 匹配 `/flag`）；而 null byte 绕过针对的是"字符串截断"，是另一类漏洞。

### RCELABS-6：屏蔽符特别多时，用绝对路径

过滤符号特别多、拼不出相对路径时，可以用**绝对路径**直接指向命令，绕开一大片符号限制。

### RCELABS-7：空格被过滤

空格被过滤时，可以用两种办法：

- **URL 编码**：空格编码成 `%20`（或 `+`）；
- **`$IFS` 的默认值**：`$IFS` 是 shell 的内部字段分隔符，默认包含空格、TAB、换行，所以 `cat${IFS}/flag` 里的 `${IFS}` 展开后就是一个空格。

```bash
# 实测（bash 5.3.15）
$ echo a${IFS}b
a b
```

### RCELABS-9（后半）：字母被过滤 → 八进制 ASCII

当字母都被屏蔽、数字还没被屏蔽时，可以用**八进制 ASCII 码** `$'\ooo'` 来构造字符，从而绕开对字母的过滤。

关键细节：**空格不可以被转换**。比如 `ls -l` 对应的八进制是 `$'\154\163\40\55\154'`，但这样写**不能**达到效果——它只能拆成三部分：

```text
$'\154\163'   +   一个真正的空格   +   $'\55\154'
```

为什么？因为 `$'...'` 整体只会产生**一个词**，写在里面的 `\40` 只是这个词内部的一个空格字符，**不会触发分词**。实测：

```bash
$ echo $'\154\163'              # 裸写，正常展开
ls
$ echo "$'\154\163'"            # 放在双引号里，不展开
$'\154\163'
$ echo $'\154\163\40\55\154'    # 看着像两个词，其实是"一个参数"
ls -l
```

最后一条最容易被骗：它打印出来是 `ls -l`，但 shell 只收到了**一个参数**，内容是 `ls -l`（含空格），所以**命令名不是 `ls`**。要真正把命令和参数分开，必须写成 `$'\154\163' $'\55\154'`。

### RCELABS-10：数字也被过滤（只留 0 和 1）→ 二进制

数字只剩下 `0` 和 `1` 没被过滤时，就用**二进制**来构造需要的数字——bash 的算术展开 `$(( ))` 支持进制写法和位移：

```bash
$ echo $((2#101))     # 二进制写法
5
$ echo $((1<<3))      # 位移：1 左移 3 位
8
```

`0` 和 `1` 加上算术运算符，就能凑出任何被过滤掉的数字。

> **PS：URL 里 `#` 的坑**
> `#` 是 URL 里 fragment 的起点，浏览器**只把 `#` 之前的部分发给服务器**。
> 所以如果 payload 用到了 `#`，在 URL 里要写成 `%23`——**过滤是应用层负责的，而过滤时编码已经被解析成 `#` 了**。

### RCELABS-11 / 12：用 `${#}` 和 `${##}` 造出 0 和 1

- 当 `1` 也被过滤时，用 **`${##}`** 替换 `1`；
- 当 `0` 也被过滤时，用 **`${#}`** 替换 `0`（RCELABS-12）。

这不是玄学，是 bash 的参数展开规则：

- `${#}` 表示**位置参数的个数**（也就是 `$#`）——没有额外参数时它就是 `0`；
- `${##}` 表示**参数 `${#}` 展开结果的长度**——`${#}` 是字符 `"0"`，长度就是 `1`。

实测（`set --` 用来设置位置参数）：

```bash
$ set --;        echo ${#} ${##}
0 1
$ set -- x;      echo ${#} ${##}
1 1
$ set -- a b c d e f g h i j;  echo ${#} ${##}
10 2        # 注意：参数个数变成两位数后，${##} 也跟着变成 2
```

> 所以 `${#}` / `${##}` 只在"没有位置参数"的前提下等于 `0` / `1`，本质上是在"数数字的位数"。

### RCELABS-13：过滤更严格 → `$(( ))` + 取反构造任意数字

当连能用的数字都没了，就用**算术展开 + 按位取反**硬造数字。原理是：

- `~x` 等于 `-x-1`（按位取反）；
- 从 `0` 出发，交替用 `~` 和 `-`，就能一路造出所有整数。

实测：

```bash
$ echo $((~0))                     # ~0 = -1
-1
$ echo $((-~0))                    # 把 -1 再取负 = 1
1
$ echo $((~-~0))                   # ~1 = -2
-2
$ echo $((-~-~0))                  # 2
2
$ echo $((-~-~-~-~-~0))            # 5
5
```

另外注意：`&&` 在 URL 里要写成 **`%26%26`**，因为 `&` 在 URL 里是参数分隔符，直接写会被拆断。

### RCELABS-14：只让用 7 个字符 → 通配符决胜

只允许 7 个字符时，先想办法"看一眼"目录里有什么（比如用 `ls`），再用**通配符**指过去：

```bash
cat /*g
```

`c` `a` `t` `空格` `/` `*` `g` —— **正好 7 个字符**。`/*g` 会被 shell 展开成"根目录下以 g 结尾的东西"，也就是 `/flag`。

实测（在临时目录里放一个 `flag`）：

```bash
$ echo /tmp/rceglob/*g
/tmp/rceglob/flag
```

> 我的笔记原话："只让使用 7 个字符，用 ls 看一眼就可以使用通配符了，我是天才 `cat /*g`" ——这关的思路确实是"不猜文件名，让 shell 自己展开"。

## 四、关卡速查

| 关卡 | 核心困难 | 需要理解的事情 |
| --- | --- | --- |
| Level 9 | 允许直接输入八进制数字 | 可以把命令和参数写成两个独立的 `$'...'` 词 |
| Level 10 | 禁止输入部分数字 | 需要想办法**生成**所需的字符，而不是直接敲数字 |
| Level 11 | 数字限制更严格 | 还要处理剩余数字的限制，并让生成的命令文本被正确解析 |

后两关的重点，不只是生成字符，还要搞清楚**生成的字符是作为普通字符串使用，还是作为新的 Shell 脚本文本执行**。

## 五、把这几个机制串起来

1. **过滤的层次**：语言层（PHP）→ shell 层（分词、展开）→ 系统层（执行哪个 sh）。payload 能不能打通，取决于它落在哪一层、在哪一层被解析。
2. **shell 的展开顺序**：变量展开、算术展开 `$(( ))`、参数展开 `${...}`、通配符展开发生在**执行之前**——所以"被过滤的字符"可以在展开阶段才出现，从而绕过只看原始字符串的过滤。
3. **空格是最先被盯上的**：URL 编码、`$IFS`、八进制里额外补空格，本质上都是在"想办法交出一个真正的空格"。
4. **数字和字母都没了怎么办**：用 `${#}`/`${##}` 拿 0 和 1，用 `$(( ))` 的取反和位移造任意数，用 `$'...'` 把八进制还原成字符——限制越死，payload 越像"拼图"。
