# AstrBot 部署与运维手册

> 整理人：早濑优香 | 整理日期：2026-08-05
> 适用场景：服务器部署实操参考



## 1. AstrBot 是什么

AstrBot 是 **Python 编写的开源聊天机器人框架**，可接入 QQ、微信等多种 IM 平台。

**确认它是 Python 项目的三个证据：**

- 发布在 PyPI 上，通过 pip/uv 安装（Python 包管理器生态）
- 运行进程是 `python3 .../astrbot run`（Python 解释器）
- 源码目录为标准 Python 包结构（`cli/`、`core/`、`api/`、`dashboard/` 均为 `.py` 模块）

---

## 2. 部署方式总览

| 方案       | 方式                                                                                                | 适用场景      |
| -------- | ------------------------------------------------------------------------------------------------- | --------- |
| 一键脚本     | `curl -sSL https://astrbot.app/install.sh \| bash`                                                | 快速跑起来     |
| Docker   | `docker run -d --name astrbot -v /path/to/data:/AstrBot/data -p 6185:6185 soulter/astrbot:latest` | 环境隔离、方便升级 |
| pip / uv | `uv tool install astrbot` → `astrbot run`                                                         | 干净、可升级，推荐 |
| 源码运行     | `git clone` + `pip install -r requirements.txt` + `python main.py`                                | 二次开发      |

**推荐排序：** 日常使用 → 一键脚本/uv；干净隔离 → Docker；二次开发 → 源码。

---

## 3. uv 安装的特点

uv 是 **Rust 编写的 Python 包管理器**，特点如下：

1. **安装速度极快**：Rust 实现，比 pip 快 10~100 倍
2. **环境自动隔离**：`uv tool install` 创建独立虚拟环境，不污染系统 Python
3. **命令直接可用**：装完自动生成 `astrbot` 命令入口
4. **升级简单**：`uv tool upgrade astrbot` 一条命令完成
5. **自带 Python 版本管理**：系统没有 Python 也能自动下载
6. **缓存复用**：全局缓存依赖包，重复安装省流量省时间

---

## 4. uv 与 systemd 的分工

**这是两个独立的概念，不要混淆：**

- **uv 负责"安装"**：把程序装好、能运行（关终端就没了）
- **systemd 负责"守护"**：让程序常驻后台、开机自启、崩溃自动恢复

> uv 安装 ≠ 自动写入 systemd。systemd 服务是手动创建的，属于部署流程中的"守护"步骤。

---

## 5. systemd 服务配置详解

实际使用的 `astrbot.service` 文件：

```ini
[Unit]
Description=AstrBot Service
After=network.target            # 网络就绪后再启动

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu
Environment=PATH=/home/ubuntu/.local/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/home/ubuntu/.local/bin/astrbot run   # 启动命令
Restart=always                  # 崩溃自动重启
RestartSec=5                    # 崩溃后5秒拉起
StandardOutput=append:/home/ubuntu/data/logs/astrbot_service.log
StandardError=append:/home/ubuntu/data/logs/astrbot_service.log

[Install]
WantedBy=multi-user.target      # 开机自启挂载点
```

**安装与启用：**

```bash
sudo cp astrbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable astrbot    # 开机自启
sudo systemctl start astrbot     # 启动
```

## 6. 运行状态与日志查看

```bash
sudo systemctl status astrbot          # 查看服务状态（active running = 正常）
sudo journalctl -u astrbot -f          # 实时滚动日志（Ctrl+C 退出）
sudo journalctl -u astrbot -n 50       # 最近50行日志
tail -f /home/ubuntu/data/logs/astrbot_service.log   # 查看日志文件

sudo systemctl restart astrbot         # 重启
sudo systemctl stop astrbot            # 停止
sudo systemctl start astrbot           # 启动
```

---

## 7. journalctl 常用参数

| 参数 | 含义 | 示例 |
|------|------|------|
| `-u` | unit，指定服务 | `journalctl -u astrbot` |
| `-f` | follow，实时滚动 | `journalctl -f` |
| `-n` | number，显示最近N行 | `journalctl -n 50` |
| `--since` | 按时间过滤 | `journalctl --since "1 hour ago"` |
| `-e` | 跳到日志末尾 | `journalctl -e` |

**记忆口诀：** `-u` 挑服务，`-f` 看直播，`-n` 限量，`--since` 定时。

## 8. 数据备份方案

### 自动备份（推荐，已配置）

- 每天凌晨 3:00 自动执行 `backup_astrbot.sh`
- 保留最近 7 天备份，存放于 `/home/ubuntu/backups/`
- 备份内容：数据库、配置文件、插件数据、账本

```bash
ls -la /home/ubuntu/backups/    # 查看已有备份
```

### 手动备份

```bash
bash /home/ubuntu/scripts/backup_astrbot.sh
```

### 无脚本的原始备份方法

```bash
# tar 打包（推荐）
tar -czf ~/backup_$(date +%Y%m%d).tar.gz -C /home/ubuntu data

# cp 复制整个目录
cp -r /home/ubuntu/data /home/ubuntu/data_backup_0805

# 只备份关键文件
cp /home/ubuntu/data/data_v4.db ~/backup/
cp /home/ubuntu/data/plugins/astrbot_plugin_ledger/ledger_data.json ~/backup/
```

### 恢复备份

```bash
sudo systemctl stop astrbot                       # 先停服务
cd /tmp && tar -xzf /home/ubuntu/backups/astrbot_最新日期.tar.gz
sudo cp -r data/* /home/ubuntu/data/             # 覆盖数据（慎用）
sudo systemctl start astrbot                      # 重启服务
```

## 9. 服务器故障排查顺序

**口诀：先网络，再资源，后服务，最后日志。**

| 层级 | 命令 | 检查内容 |
|------|------|----------|
| 网络 | `ping -c 4 8.8.8.8` / `ping -c 4 baidu.com` | 外网连通 / DNS解析 |
| 资源 | `free -h` / `df -h` / `top` | 内存、磁盘（80%故障根源）、CPU负载 |
| 服务 | `sudo systemctl status astrbot nginx` / `ss -tlnp` | 服务状态、端口监听 |
| 日志 | `journalctl -u astrbot -n 50` / `tail -50 日志文件` | 找根因 |
| 兜底 | `journalctl -xe` | 系统级错误 |

## 10. 服务中断排查五步法

**第1步：确认状态**
```bash
sudo systemctl status astrbot
```
看 `Active:` 是否为 `failed`/`inactive`。

**第2步：翻日志（最关键）**
```bash
sudo journalctl -u astrbot -n 50
```
崩溃前最后几十行通常直接写着原因。

**第3步：查资源**
```bash
df -h    # 磁盘满没满
free -h  # 内存够不够（OOM 是常见元凶）
```

**第4步：手动复现**
```bash
sudo systemctl stop astrbot
astrbot run    # 前台直接跑，报错直接打在屏幕上
```

**第5步：修复 + 重启验证**
改配置 → `systemctl daemon-reload` → `systemctl start astrbot` → `status` 确认 → 观察稳定。

## 12. 技术背景：Rust 与 Python

**Rust 是什么：** 系统级编程语言，性能和 C/C++ 同级，但更安全。

| 对比 | Python | C | Rust |
|------|--------|---|------|
| 类比 | 自动驾驶汽车（好开但慢） | 手动挡赛车（快但易事故） | 带安全气囊的赛车（快且安全） |
| 性能 | 慢（解释执行） | 快（编译执行） | 快（编译执行） |
| 安全 | 内存安全 | 需手动管理，易出bug | 编译器强制内存安全 |
| 应用 | Web、AI、脚本 | 系统底层 | 底层工具（uv、Firefox引擎等） |

**为什么这样分工：** uv 用 Rust 写 → 快；AstrBot 用 Python 写 → 好开发好维护。两者互补。
