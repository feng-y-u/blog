# Python 模块：标准模板、作用域、第三方模块与搜索路径

Python 内置了很多**模块**，只要安装完毕，这些模块就可以立即使用。编写程序时经常引用其他模块（Python 内置模块或第三方模块），使用模块可以避免函数名、变量名冲突——不同模块中的同名函数互不影响。

## 模块的标准文件模板

以 `hello.py` 为例：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

' a test module '

__author__ = 'Michael Liao'

import sys

def test():
    args = sys.argv
    if len(args) == 1:
        print('Hello, world!')
    elif len(args) == 2:
        print('Hello, %s!' % args[1])
    else:
        print('Too many arguments!')

if __name__ == '__main__':
    test()
```

逐行说明：

1. **第 1 行**：表示让这个 `hello.py` 文件在 Unix/Linux/Mac 上可以直接运行（Windows 会忽略）。
2. **第 2 行**：注释表示 `.py` 文件本身使用 **UTF-8 编码**。
3. **第 4 行**：一个字符串，表示模块的**文档注释**——任何模块的第一个字符串都被视为模块的文档注释。
4. **第 6 行**：使用 `__author__` 变量把作者写进去，这样公开源码后代表你是作者。
5. 以上是 Python 模块的标准文件模板，**后面才是真正的代码部分**。

导入 `sys` 模块后，我们就有了一个指向该模块的变量 `sys`，使用这个变量就可以访问 `sys` 模块的所有功能。

### sys.argv：命令行参数

`sys` 模块有一个 `argv` 变量，使用 list 存储命令行的所有参数。**命令行参数**指的是在命令行执行 python 文件时、`py` 语句后带的参数，所以 `argv` **至少有一个元素**——该文件的文件名：

```bash
$ python3 hello.py Michael
```

此时 `sys.argv == ['hello.py', 'Michael']`，于是 `test()` 会输出 `Hello, Michael!`。

### `if __name__ == '__main__'`

```python
if __name__ == '__main__':
    test()
```

这行代码最常被用于**运行测试**。

`__name__` 是 Python 自动给每个 `.py` 文件设置的一个**内置变量**：

- 当**直接运行**这个 `.py` 文件时，`__name__` 的值为 `'__main__'`；
- 当这个文件被别的文件 **import** 时，`__name__` 的值为**模块名**（也就是文件名）。

所以 `if __name__ == '__main__':` 就是在判断"是不是在被直接运行"：直接运行时执行 `test()` 测试代码；被 import 时跳过测试代码，只把函数等接口暴露给导入方。

## 作用域

在一个模块中可能有很多函数和变量，但它们的权限不一样：有的是公开的，有的是私有的。Python 使用**前缀 `_`** 实现这种约定：

- **正常定义的函数和变量名都是公开的**（public），可以被直接引用，如 `abc`、`x123`。
- 类似 `__xxx__` 的变量是**特殊变量**，可以被直接引用，但有特殊用途，比如 `__author__`、`__name__`、`__doc__`。自己的变量不要用这种命名。
- 类似 `_xxx` 和 `__xxx` 这样的函数或变量是**非公开的**（private），**不应该**被直接引用。

为什么是"不应该"而不是"不能"？因为 **Python 没有方法完全限制访问 private 函数或变量**——这纯粹是编程习惯上的约定。

规范：**外部不需要引用的函数全部定义成 private，只有外部需要引用的函数才定义为 public**。

## 安装第三方模块

使用 **pip** 命令安装第三方库。Mac 或 Linux 上有可能并存 Python 3.x 和 Python 2.x，因此对应的 pip 命令是 `pip3`。

一般来说，第三方库都会在 Python 官方的 [pypi.python.org](https://pypi.python.org/) 网站注册（现在官方站点为 [pypi.org](https://pypi.org/)）。要安装一个第三方库，必须先知道该库的名称，可以在官网或 PyPI 上搜索。比如 Pillow 的名称叫 [Pillow](https://pypi.python.org/pypi/Pillow/)，安装命令就是：

```bash
pip install Pillow
```

### 安装常用模块

直接使用 [Anaconda](https://www.anaconda.com/)，这是一个基于 Python 的**数据处理和科学计算平台**，已经内置了许多非常有用的第三方库。可以从 [Anaconda 官网](https://www.anaconda.com/download/) 下载 GUI 安装包，装好后常用库开箱即用，不需要单独 pip 安装。

## 虚拟环境（venv，Python 3.3+）

同时开发多个应用时，各自需要的第三方库版本可能不同（比如应用 A 需要 jinja2 2.7，应用 B 需要 jinja2 2.9），共用一个系统 Python 环境就会冲突。解决方案是**虚拟环境**：把 Python 环境"复制"到当前目录的子目录，在该子目录中安装独立的第三方库，互不影响。Python 3.3+ 内置了 `venv` 模块，创建虚拟环境不需要额外安装。

bash（Mac / Linux）中的用法：

```bash
# 1. 创建虚拟环境：在当前目录生成 .venv 目录（独立的 Python 运行环境）
python3 -m venv .venv

# 2. 激活虚拟环境：激活后命令行提示符会出现 (.venv) 前缀
source .venv/bin/activate

# 3. 激活后安装第三方库——只会装进当前虚拟环境，不影响系统全局
pip install Pillow

# 4. 退出虚拟环境
deactivate
```

要点：

- `python3 -m venv .venv` 中的 `-m` 表示以**模块方式**运行（`python3 -m 模块名` 是运行 Python 模块的标准方式，pip 对应 `python3 -m pip install xxx`）；
- 激活后 `pip install` 的库只属于该虚拟环境，**不影响系统全局环境**；不同应用各建各的虚拟环境，互不干扰；
- 删除虚拟环境只需删掉 `.venv` 目录（`rm -rf .venv`），不留残留。

> **bash 要点**：激活必须用 `source .venv/bin/activate`，不能直接执行 `.venv/bin/activate`——直接执行会启动一个子进程，子进程里设置的环境变量**无法传回当前 shell**；`source` 是在**当前 shell 内**执行脚本，所以才能生效。
> **Windows 下的激活命令不同**：CMD 用 `.venv\Scripts\activate.bat`，PowerShell 用 `.venv\Scripts\Activate.ps1`。

bash 常用命令小抄（venv / pip 工作流）：

| 命令 | 作用 |
| --- | --- |
| `cd 目录名` | 进入目录 |
| `ls` | 列出当前目录的文件 |
| `python3 -m venv .venv` | 创建虚拟环境 |
| `source .venv/bin/activate` | 激活虚拟环境（bash） |
| `pip install 库名` | 安装第三方库（激活后装进当前环境） |
| `deactivate` | 退出虚拟环境 |
| `python --version` | 查看当前使用的 Python 版本 |

## 模块搜索路径

当我们加载一个模块时，Python 会在**指定的路径**下搜索对应的 `.py` 文件。

默认情况下，Python 解释器会搜索**当前目录**、所有已安装的**内置模块**和**第三方模块**。搜索路径存放在 `sys` 模块的 `path` 变量中：

```python
>>> import sys
>>> sys.path
['', '/Library/Frameworks/Python.framework/Versions/3.6/lib/python36.zip', '/Library/Frameworks/Python.framework/Versions/3.6/lib/python3.6', ..., '/Library/Frameworks/Python.framework/Versions/3.6/lib/python3.6/site-packages']
```

（第一个空字符串 `''` 表示当前目录，具体输出与环境有关。）

如果我们要添加自己的搜索目录，有两种方法：

**方法一：修改 `sys.path`，添加要搜索的目录：**

```python
>>> import sys
>>> sys.path.append('/Users/michael/my_py_scripts')
```

**方法二：设置环境变量 `PYTHONPATH`。** 该环境变量的内容会被**自动添加**到模块搜索路径中，设置方式与设置 Path 环境变量类似。注意只需要添加我们自己的搜索路径，**Python 本身的搜索路径不受影响**。
